# M3 advanced answer key

1. A — Missing/incorrect context is the first boundary to inspect.
2. A — Retrieval adds complexity without an information gap.
3. A — Stable typed downstream fields justify structured output.
4. A — Fine-tuning changes repeatable behavior/style when data supports it; retrieval supplies facts.
5. A — Dynamic intermediate decisions and tools justify an agent.
6. A — Different phases can have different economics and capability needs.
7. A — Shape, policy, then approval/action is the safe order.
8. A — Written decisions preserve assumptions and ownership context.
9. A — Add the smallest grounding boundary that addresses the missing facts.
10. A — Simpler patterns reduce operational surface area.
11. Whether dynamic steps and private facts require composition (for example, retrieval inside an agent) and what the primary acceptance criteria are.
12. Deterministic authorization/business-policy validation is missing; schema checks shape, not whether the requested account is allowed.
13. Source grounding, chunk/retrieval selection, prompt assembly, and citation/faithfulness evaluation—not merely answer relevance.
14. Direct call → summary quality/length criterion; structured output → parse/field accuracy criterion; retrieval → groundedness/recall criterion; agentic → task completion and tool-safety criterion.
15. Example: prompted structured extraction with a fast/default model; reject an agent because preview is not dynamic multi-step work; enforce allocation/authorization policy before approval; reconsider if parse rate, groundedness, latency, or policy-review rate misses the target.
